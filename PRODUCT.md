# Product

## Register

product

## Users

Visitors and developers exploring Meridian who want to understand how a shared AI interface can present multiple providers and model capabilities.

## Product Purpose

Provide an interactive, visual-only playground that demonstrates model selection, provider status, a chat composition surface, local image preview, and illustrative performance indicators. Success means visitors can explore the interface and understand the ecosystem without API calls, credentials, or backend setup.

## Brand Personality

Clear, technically credible, open, and restrained. The experience should feel familiar to developers and consistent with Meridian's white technical editorial direction.

## Anti-references

Do not imply that an API is connected when it is not. Do not request or store real API keys. Avoid generic SaaS dashboard decoration, fictional live performance claims, and interface patterns that obscure the demo-only boundary.

## Design Principles

- Make the visual-only boundary explicit wherever simulated behavior appears.
- Keep all interactions reversible and local to the browser.
- Preserve Meridian's existing navigation, typography, color roles, and component language.
- Demonstrate capability through usable controls rather than explanatory walls of text.

## Accessibility & Inclusion

Use semantic controls, visible focus treatment, descriptive accessible labels, keyboard-operable model selection and messaging, readable contrast, responsive layouts, and reduced-motion support. The image preview remains local to the browser.
