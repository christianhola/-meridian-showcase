# Meridian Community Discord — server blueprint

**Status:** proposed structure; no Discord server or invitation link is verified.

## INFORMATION
- `#rules-and-faq`: code of conduct, security and moderation policies (read-only).
- `#announcements`: official announcements only (read-only).
- `#releases`: release links and release notes.

## COMMUNITY
- `#general-chat`: casual discussion.
- `#introductions`: new members.
- `#showcase`: projects with source links, screenshots and consent to share.
- `#feedback`: product and community feedback.

## OPEN SOURCE DEVELOPMENT
- `#contributors-lounge`: contributor questions and mentoring.
- `#pr-reviews`: links to PRs, no credentials or logs with tokens.
- `#mcp-and-plugins`: protocol design and extension contracts.
- `#help-technical`: community-supported development questions.
- `#templates-and-sdks`: starter kits and client libraries.

## INTERNATIONAL
- `#english`, `#espanol`: language-specific support.
- Expand only when there are active volunteer moderators.

## MODERATION / PRIVATE
- `#mod-triage`: moderation only.
- `#incident-reports`: private reporting intake, not visible to the public.

## Roles
- **Community member:** read and participate after rule acknowledgment.
- **Contributor:** publicly credited after approved contributions; no special repository rights.
- **Core Contributor:** consistent, verified contributions; role is recognition, not a secret-access grant.
- **Community Maintainer:** assigned after review; permissions scoped to relevant channels and repos.
- **Moderator:** safety operations, independent from merge rights.
- **Organization Owner:** organization configuration, security and access recovery.

## Before inviting users
1. Set minimum verification and enable AutoMod and anti-spam.
2. Appoint human moderators in at least the launch languages.
3. Publish rules and escalation/appeal process.
4. Configure private safety intake and incident response.
5. Test onboarding and all permissions with a non-moderator account.
6. Add an invite link only after its creation and verification.

Never invent participant counts, partner roles, grants, hackathon prizes or invitations.
